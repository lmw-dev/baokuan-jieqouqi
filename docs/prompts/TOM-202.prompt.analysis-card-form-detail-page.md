## 🔧 具体要求与约束 (Requirements & Constraints)

### 技术栈约束
- **语言**: TypeScript (strict mode)
- **架构模式**: Next.js App Router + React Hook Form + Prisma ORM
- **性能要求**: 页面加载时间 < 2秒，表单保存响应 < 500ms
- **UI框架**: Tailwind CSS + shadcn/ui组件库
- **表单管理**: React Hook Form + Zod验证
- **状态管理**: 组件级状态管理，必要时使用Zustand

### 功能要求

#### 核心功能
1. **动态路由页面**: `/cards/[cardId]/edit` 支持卡片ID参数
2. **9个核心字段完整编辑**:
   - `versionTitle`: 版本标题 (必填，1-50字符)
   - `hookCopy`: 钩子文案 (可选，最大1000字符)
   - `hookTypes`: 钩子类型标签 (可选，最多5个)
   - `hookNotes`: 钩子笔记 (可选，最大500字符)
   - `coreIdea`: 核心观点 (可选，最大800字符)
   - `argumentCase`: 论证案例 (可选，最大1000字符)
   - `valueDelivery`: 价值交付标签 (可选，最多8个)
   - `reusableElements`: 可复用要素 (可选，最大600字符)
   - `valueNotes`: 价值点笔记 (可选，最大500字符)

3. **编辑/保存模式切换**:
   - `view`模式: 只读展示，格式化内容
   - `edit`模式: 表单编辑，实时验证
   - 模式切换带确认机制（未保存变更时）

4. **权限控制**: 只有卡片创建者可以访问编辑页面
5. **数据保存**: 表单提交后更新数据库并显示成功反馈

#### 布局要求
- **3个主要区块**: 钩子分析、核心观点、价值交付
- **响应式设计**: 桌面端2列布局，移动端单列布局
- **字段分组**: 逻辑相关的字段组合展示

### 质量标准
- **TypeScript严格模式**: 所有类型完整定义，无any类型
- **测试覆盖率**: 核心组件 ≥ 85%，Hook逻辑 ≥ 90%
- **用户体验**: 表单响应 < 200ms，加载状态明确，错误提示友好
- **安全性**: 前后端双重权限验证，SQL注入防护

### 类型安全要求 (🛡️ Type Safety)
- **类型优先设计**: 先基于Prisma模型定义完整TypeScript接口
- **接口一致性**: 表单数据类型与数据库模型完全匹配

### 常见Bug预防 (基于经验总结)

#### 1. 权限验证错误预防
- ❌ **错误做法**: 只在前端检查权限，后端未验证
- ✅ **正确做法**: 前后端都进行权限验证，后端作为最终安全屏障

#### 2. 表单数据类型不匹配预防
- ❌ **错误做法**: 表单提交的数据类型与Prisma模型不一致
- ✅ **正确做法**: 基于Prisma模型生成Zod schema，确保类型一致性

#### 3. 编辑模式状态混乱预防
- ❌ **错误做法**: 编辑模式状态分散在多个组件中
- ✅ **正确做法**: 集中管理编辑模式状态，使用Context或专用Hook

#### 4. 数据保存失败处理预防
- ❌ **错误做法**: 保存失败时不给用户明确反馈
- ✅ **正确做法**: 详细的错误信息提示 + 重试机制 + 数据恢复
